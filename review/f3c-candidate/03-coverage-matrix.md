## How identity is asserted before every behavioral run
The harnesses that deploy the F3B artifact (`data/escrow-custody-v3-build.json`) compare the deployed runtime keccak to the repo-owned pin (`verifier/v4-candidate-identity-31337-v3.json`) BEFORE any flow:
- `scripts/test-v3-integrated-flow.cjs`: deploy → `v3_ident` check (runtime hash equals identity) → flows.
- `scripts/test-f3c-two-worker-contention.cjs`: same pattern (v3art + identity runtime check).
- `scripts/_f3c-v4-export-producer.cjs`: same pattern; each export's separate-process verifier additionally re-checks `verify-v4.js` identity at the settlement block.
- Result record files (`evidence/phase3b-v4/results.json`, `evidence/phase3c-v4/run-record.json`, `evidence/f3c-v4-exports/results.json`) stamp `runtimeHash`/revision and `noPublicFinality: true`.
