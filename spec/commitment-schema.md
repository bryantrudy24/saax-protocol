# SAAX Commitment Schema

This document is the canonical JSON schema for a SAAX commitment. It defines the full field list, each field's type and required/optional status, the canonical hashing rules, the canonical signing rules, and an example commitment object.

A SAAX commitment is a machine-readable, cryptographically-bound record of an economic agreement between autonomous parties. It describes what was authorized, what was committed, what proves fulfillment, what happens on failure, how settlement is linked, and when the commitment becomes final.

## 1. Top-level fields

| Field | Type | Required | Description |
|---|---|---|---|
| `commitmentId` | string (0x-hex, 32 bytes) | **required** | Unique commitment identifier, generated by the issuer at creation; the root of the audit chain |
| `parties` | object | **required** | The parties to the commitment (`buyer`, `seller`, `signer`, optional `authorityRef`) |
| `authorityReference` | string (URI) | optional | Reference to an external authority proof (see `authority-proof-interface.md`); when absent, the buyer's signature is the authorization |
| `requestedOutcome` | object | **required** | The capability/outcome being requested (description, category, desired result shape) |
| `providerObligation` | object | **required** | What the provider commits to deliver: description, quantifiable target, constraints |
| `commercialTerms` | object | **required** | Price, currency, fee schedule, and payment obligation of the commitment |
| `paymentTerms` | object | **required** | Settlement instructions: amount, asset, rail-agnostic settlement requirement reference (R) |
| `acceptanceCriteria` | array | **required** | Objective criteria that define successful fulfillment; each entry may carry a verification policy |
| `verificationPolicy` | object | optional | Default verification policy applied to criteria that do not specify their own |
| `evidenceRequirements` | object | optional | Evidence the provider must supply: required types, minimum counts, maximum age, accepted issuers |
| `evidenceReferences` | array | optional | References to evidence records bound to the commitment after evaluation |
| `deadline` | string (ISO-8601 UTC) | **required** | The time by which fulfillment must complete |
| `timeoutConditions` | array | optional | Conditions that trigger a timeout transition |
| `failureConditions` | array | **required** | Conditions that constitute failure |
| `recoveryPolicy` | object | optional | Policy governing recovery after failure: retry budget, refund rules, compensation |
| `refundsCompensation` | object | optional | Refund/compensation terms on failure or partial completion |
| `disputeState` | object | optional | Dispute status and references when a dispute is open |
| `settlementReferences` | array | optional | Settlement references (rail, credential, transaction reference) after settlement |
| `executionReceipts` | array | optional | Receipts of execution events (provider side) |
| `outcomeReceipt` | object | optional | The final outcome receipt after verification |
| `lifecycleState` | string (enum) | **required** | The current lifecycle state (see `lifecycle.md`) |
| `signaturesProofs` | object | **required** | Signatures over the canonical commitment digest by the parties; optional proof references |
| `auditChain` | array | **required** | Append-only log of state transitions with hashes; root is `commitmentId` |
| `finalResolution` | object | optional | Terminal resolution: final state, resolution reason, timestamp, references |

## 2. Nested structures

### 2.1 `parties`

| Field | Type | Required |
|---|---|---|
| `buyer` | string (0x-address) | **required** |
| `seller` | string (0x-address) | **required** |
| `signer` | string (0x-address) | optional — the broadcaster of on-chain settlement |
| `authorityRef` | string (URI) | optional — reference to the authority proof used at issuance |

### 2.2 `commercialTerms`

| Field | Type | Required |
|---|---|---|
| `currency` | string (e.g. `USD`) | **required** |
| `price` | string (decimal, micro-units of asset) | **required** |
| `fee` | string (decimal) | optional |
| `feePayer` | string enum: `buyer` \| `seller` \| `split` | optional |

### 2.3 `paymentTerms`

| Field | Type | Required |
|---|---|---|
| `amount` | string (decimal, micro-units) | **required** |
| `asset` | string (0x-address or CAIP-19 asset) | **required** |
| `settlementRequirement` | object (R) | **required** — the rail-agnostic settlement requirement: `{ rail: string|null, amount, asset, recipient, chainId, deadline }`; `rail: null` means any registered rail |
| `rail` | string | optional — deprecated in favor of `settlementRequirement.rail`; when set, names the chosen rail at commitment time |

### 2.4 `acceptanceCriteria[]` entry

| Field | Type | Required |
|---|---|---|
| `criterionId` | string | **required** |
| `description` | string | **required** |
| `requiredEvidenceType` | string | optional — enforced when a verification policy references it |
| `verificationPolicy` | object | optional — overrides the commitment default |

### 2.5 `verificationPolicy`

| Field | Type | Required |
|---|---|---|
| `criterionId` | string | optional — policy applies to this criterion |
| `criterionDescription` | string | optional |
| `requiredEvidenceType` | string | optional |
| `acceptedIssuers` | array (0x-addresses) | optional — allowlist; when present, evidence from unlisted issuers fails |
| `verificationScheme` | string enum: `eip712` \| `cose` \| `jws` | **required** |
| `evaluationLogic` | string | optional — a safe comparison expression over payload fields, e.g. `payload.temperature <= 5` |
| `maxEvidenceAge` | integer (seconds) | **required** |
| `minimumEvidenceCount` | integer | **required** |

### 2.6 `evidenceRequirements`

| Field | Type | Required |
|---|---|---|
| `requiredTypes` | array of string | optional |
| `minimumCountPerType` | integer | optional |
| `maxAgeSeconds` | integer | optional |
| `acceptedIssuers` | array | optional |

### 2.7 `recoveryPolicy`

| Field | Type | Required |
|---|---|---|
| `maxRetries` | integer | optional |
| `retryIntervalSeconds` | integer | optional |
| `refundOnFailure` | boolean | **required** |
| `compensationPercent` | string (decimal) | optional |

### 2.8 `disputeState`

| Field | Type | Required |
|---|---|---|
| `open` | boolean | **required** |
| `raisedBy` | string enum: `buyer` \| `seller` \| `signer` \| `authority` | optional |
| `reason` | string | optional |
| `reference` | string (URI) | optional |

### 2.9 `signaturesProofs`

| Field | Type | Required |
|---|---|---|
| `commitmentDigest` | string (0x-hex 32 bytes) | **required** — the canonical hash |
| `signatures` | object | **required** — `{ buyer?: string, seller?: string, signer?: string, authority?: string }` |
| `scheme` | string enum: `eip712` \| `cose` \| `jws` | **required** |
| `proofReferences` | array of URI | optional — references to external authority proofs |

### 2.10 `auditChain[]` entry

| Field | Type | Required |
|---|---|---|
| `state` | string | **required** |
| `transition` | string | optional |
| `at` | string (ISO-8601) | **required** |
| `by` | string (0x-address) | **required** |
| `prevHash` | string (0x-hex) | **required** — hash of the previous entry (root: `commitmentId`) |
| `entryHash` | string (0x-hex) | **required** — hash of this entry |

## 3. Canonical hashing rules

**Algorithm:** SHA-256.

**What gets hashed:** the canonical serialization of all commitment fields **except** the volatile `lifecycleState`, `settlementReferences`, `executionReceipts`, `outcomeReceipt`, `disputeState` open/close, and `auditChain` — state-dependent fields are recorded in the audit chain, not in the base digest.

**Serialization order (canonical):**

1. `commitmentId`
2. `parties` — serialized with keys sorted lexicographically
3. `authorityReference` (empty string when absent)
4. `requestedOutcome` — keys sorted lexicographically
5. `providerObligation` — keys sorted lexicographically
6. `commercialTerms` — keys sorted lexicographically
7. `paymentTerms` — keys sorted lexicographically
8. `acceptanceCriteria` — array order as authored, each entry's keys sorted
9. `verificationPolicy` — keys sorted lexicographically (empty object when absent)
10. `evidenceRequirements` (empty object when absent)
11. `deadline` (ISO-8601 string)
12. `timeoutConditions` (empty array when absent)
13. `failureConditions`
14. `recoveryPolicy` (empty object when absent)
15. `refundsCompensation` (empty object when absent)

**Serialization rules:** JSON with no whitespace; object keys sorted lexicographically at every nesting level; arrays preserve authored order; numbers serialized as decimal strings where the schema types them as string.

**Digest:** `commitmentDigest = sha256(canonical_commitment_fields)` returned as lowercase 0x-hex (32 bytes).

## 4. Canonical signing rules

**What gets signed:** the `commitmentDigest` (Section 3) — never the raw object.

**Who signs:**

| Role | Required? | Meaning |
|---|---|---|
| `buyer` | **required** | Authorizes the commitment's terms and the payment obligation |
| `seller` | **required** | Accepts the obligation to fulfill |
| `signer` | optional | Authorizes the on-chain settlement broadcast (when the Router broadcasts) |
| `authority` | optional | Signs when an external authority proof is bound (see `authority-proof-interface.md`) |

**Scheme:** `eip712` is the canonical scheme with EIP-712 typed-data over the canonical digest fields; `cose` (COSE_Sign1) and `jws` are supported for evidence and proofs (see `evidence-interface.md`, `authority-proof-interface.md`). Conforming implementations must verify each party's signature over `commitmentDigest` using the party's registered verification material.

**Verification:** a commitment is validly authorized when every required signature verifies over the digest, and, when an `authorityReference` is present, the referenced authority proof is valid (structure, signature, scope, time) at evaluation time.

## 6. Conformance

Test vectors for commitments, hashing, and signing live in the [conformance suite](../conformance). A conforming implementation must produce the expected canonical digest for the given commitment objects and verify signatures per the rules above.
